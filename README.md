* **Оюутны нэр:** М.Наранбат
* **Оюутны код:** B242270801

## Хэсэг A: Category-Partition (Банкны шилжүүлгийн функц)

### Давуу эрэмбийн дүрэм (Error Priority Order)
Олон алдаа нэг хүсэлтэд зэрэг илрэх үед буцах дарааллыг дараах байдлаар тогтоов: 
`from` шалгах (`ERROR_NO_FROM` -> `ERROR_FROZEN`) -> `to` шалгах (`ERROR_NO_TO` -> `ERROR_SAME_ACCOUNT`) -> `amount / currency` шалгах (`ERROR_BAD_AMOUNT` -> `ERROR_INSUFFICIENT` -> `ERROR_LIMIT`).

### A1: Сонголт ба төлөөлөх утгын хүснэгт
| Параметр (Category) | Сонголтууд (Choices) | Төлөөлөх утгууд (Representative Values) |
| :--- | :--- | :--- |
| **from** (Шилжүүлэгч) | Хүчинтэй, Царцаагдсан, Байхгүй | `"ACC001"`, `"ACC_FROZEN"`, байхгүй ID |
| **to** (Хүлээн авагч) | Хүчинтэй, Байхгүй, Өөрийн данс (Same) | `"ACC002"`, байхгүй ID, `"ACC001"` |
| **amount** (Дүн) | Тэг/Сөрөг, Хэвийн, Үлдэгдэл хэтэрсэн, Лимит хэтэрсэн | `0` эсвэл `-100`, `50000`, `9999999` |
| **currency** (Валют) | Ижил, Өөр (Хөрвүүлэлттэй) | `"MNT"`, `"USD"` |

### A2: Хязгаарлалт, Үндэслэл ба Олонлогийн тооцоо (72 -> 48)
* **[ERROR] Үндэслэл:** Сөрөг тестийн ангилалд хамаарах тул алдаа буцаана (`Frozen`, `Missing`, `SameAsFrom`, `Zero`, `OverBalance`, `OverLimit`).
* **[SINGLE] Үндэслэл:** Тухайн параметрийн онцгой тохиолдлыг бие даан нэг удаа шалгахад хангалттай.
* **[IF/property] Үндэслэл:** Шилжүүлэгч эсвэл хүлээн авагч данс байхгүй/царцаагдсан үед мөнгөн дүн шалгах шаардлагагүй тул бусад утгуудыг `Normal` болгож хязгаарлана.
* **Бүрэн олонлогийн тоо (N):** 3 (from) x 3 (to) x 4 (amount) x 2 (currency) = **72 боломж**.
* **Хязгаарлалтын дараах тоо (M):** `IF [From] = "Missing" THEN [Amount] = "Normal"` зэрэг хязгаарлалт хэрэглэснээр утгагүй болон давхардсан 24 хослол хасагдаж **M = 48** болж буурна (72 -> 48).

### A3: Спецификацийн хүснэгт (10+ тест кейс)
| № | from | to | amount | currency | Хүлээгдэх үр дүн (Status & Result) |
|---|---|---|---|---|---|
| **1** | Хүчинтэй | Хүчинтэй | Хэвийн | Ижил | **201 OK** (Happy path) |
| **2** | Байхгүй | Хүчинтэй | Хэвийн | Ижил | **200 ERROR_NO_FROM** |
| **3** | Царцаагдсан | Хүчинтэй | Хэвийн | Ижил | **200 ERROR_FROZEN** |
| **4** | Хүчинтэй | Байхгүй | Хэвийн | Ижил | **200 ERROR_NO_TO** |
| **5** | Хүчинтэй | Өөрийн данс | Хэвийн | Ижил | **200 ERROR_SAME_ACCOUNT** |
| **6** | Хүчинтэй | Хүчинтэй | Тэг/Сөрөг | Ижил | **200 ERROR_BAD_AMOUNT** |
| **7** | Хүчинтэй | Хүчинтэй | Үлдэгдэл хэт | Ижил | **200 ERROR_INSUFFICIENT** |
| **8** | Хүчинтэй | Хүчинтэй | Лимит хэт | Ижил | **200 ERROR_LIMIT** |
| **9** | Хүчинтэй | Хүчинтэй | Хэвийн | Өөр | **201 OK** (Ханш хөрвүүлэлт амжилттай) |
| **10** | Байхгүй | Байхгүй | Хэвийн | Ижил | **200 ERROR_NO_FROM** |

## Хэсэг B: PICT (Pairwise Covering Array)

### B1: Браузерын моделийн үр дүн
* **2-way мөрийн тоо (`results/browser-2way.txt`):** **10** мөр.
* **3-way мөрийн тоо (`results/browser-3way.txt`):** **20** мөр.

### B2: Шилжүүлгийн PICT моделиудын харьцуулалт
* **transfer-nc.txt (Хязгаарлалтгүй):** **13** мөр.
* **transfer.txt (Хязгаарлалттай):** **13** мөр.
* **transfer-neg.txt (~ тэмдэглэгээтэй сөрөг утга):** **16** мөр.

---

### B2 Бодит 3 Тест Кейс (Setup, Body, Oracle)

#### Тест Кейс 1: Happy Path (Амжилттай шилжүүлэг)
* **Setup:** Данс `ACC001` (Идэвхтэй, үлдэгдэл: 100,000 MNT), Данс `ACC002` (Идэвхтэй).
* **Transfer Body (POST /transfer):**
  ```json
  { "from": "ACC001", "to": "ACC002", "amount": 50000, "currency": "MNT" }
  ```
* **Oracle:** Status **201 Created**, Body: `{"result": "OK"}`

#### Тест Кейс 2: Single Error (Царцаагдсан данс)
* **Setup:** Данс `ACC_FROZEN` (Царцаагдсан), Данс `ACC002` (Идэвхтэй).
* **Transfer Body (POST /transfer):**
  ```json
  { "from": "ACC_FROZEN", "to": "ACC002", "amount": 50000, "currency": "MNT" }
  ```
* **Oracle:** Status **200 OK**, Body: `{"result": "ERROR_FROZEN"}`

#### Тест Кейс 3: Double Error (Байхгүй данснууд)
* **Setup:** Системд `ACC999` болон `ACC888` данснууд байхгүй.
* **Transfer Body (POST /transfer):**
  ```json
  { "from": "ACC999", "to": "ACC888", "amount": 50000, "currency": "MNT" }
  ```
* **Oracle:** Status **200 OK**, Body: `{"result": "ERROR_NO_FROM"}`

## Хэсэг B3: Дүгнэлт
Энэхүү лабораторийн ажлаар Category-Partition болон PICT хэрэгслийг ашиглан тест дизайн хийж сурлаа. Гар аргаар хийх Category-Partition нь бизнесийн логик болон алдааны давуу эрэмбийг нарийн тогтоох боломжийг олгосон бол PICT нь хосын болон гурвын хамралтыг автоматаар үүсгэж үр дүнг хурдасгасан. Моделиудыг үүсгэж, results хавтас руу команд мөрөөр бүртгэн баталгаажуулсан нь чанарын баталгаажуулалтад өндөр ач холбогдолтой туршлага боллоо.
