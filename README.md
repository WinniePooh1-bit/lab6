## Хэсэг A: Category-Partition (Банкны шилжүүлгийн функц)

### Давуу эрэмбийн дүрэм (Error Priority Order)
Олон алдаа нэг хүсэлтэд зэрэг илрэх үед буцах дарааллыг дараах байдлаар тогтоов: 
`from` шалгах (`ERROR_NO_FROM` → `ERROR_FROZEN`) $\rightarrow$ `to` шалгах (`ERROR_NO_TO` → `ERROR_SAME_ACCOUNT`) $\rightarrow$ `amount / currency` шалгах (`ERROR_BAD_AMOUNT` → `ERROR_INSUFFICIENT` → `ERROR_LIMIT`).

### A1: Сонголт ба төлөөлөх утгын хүснэгт
| Параметр (Category) | Сонголтууд (Choices) | Төлөөлөх утгууд (Representative Values) |
| :--- | :--- | :--- |
| **from** (Шилжүүлэгч данс) | Хүчинтэй, Царцаагдсан, Байхгүй | `"ACC001"` (active), `"ACC_FROZEN"`, байхгүй ID |
| **to** (Хүлээн авагч данс) | Хүчинтэй, Байхгүй, Өөрийн данс (Same) | `"ACC002"`, байхгүй ID, `"ACC001"` |
| **amount** (Шилжүүлгийн дүн) | Тэг/Сөрөг, Хэвийн, Үлдэгдэл хэтэрсэн, Лимит хэтэрсэн | `0` эсвэл `-100`, `50000`, `9999999`, өдрийн лимитээс их |
| **currency** (Валют) | Ижил, Өөр (Хөрвүүлэлттэй) | `"MNT"`, `"USD"` |
| **Далд орчны сонголт** | Өдрийн лимит дүүрсэн эсэх | Лимит хүрээнд, Лимит хэтэрсэн |

### A2: Хязгаарлалт ба Олонлогийн тооцоо (N → M)
* **[ERROR]:** Утга нь алдаа үүсгэх тул сөрөг тестийн ангилалд хамаарна.
* **[SINGLE]:** Тухайн параметрийн онцгой нэг л тохиолдлыг шалгахад хангалттай.
* **[IF/property]:** Нэг параметр нөгөөгөөсөө хамааралтай байх нөхцөл.
* **Бүрэн олонлогийн тоо (N):** 3 (from) × 3 (to) × 4 (amount) × 2 (currency) = 72 боломж.
* **Хязгаарлалтын дараах тоо (M):** Хязгаарлалт хэрэглэснээр хүчингүй болон давхардсан хослолууд хасагдаж **M = 48** болж буурна (72 → 48).

## Хэсэг B: PICT (Pairwise Covering Array)

### B1: Браузерын моделийн үр дүн
* **2-way мөрийн тоо (`results/browser-2way.txt`):** 10 мөр. PICT нь greedy алгоритм ашигладаг тул хамгийн цөөн мөрийг ЗААВАЛ олох баталгаа өгдөггүй, харин хосын хамралтыг хурдан шуурхай хангадаг.
* **3-way мөрийн тоо (`results/browser-3way.txt`):** 30 мөр. Энэ нь бүрэн олонлог (144)-аас хамаагүй цөөн бөгөөд 3 хүчин зүйлийн харилцан үйлчлэлийг үр дүнтэй хамруулсан.

### B2: Шилжүүлгийн PICT моделиудын харьцуулалт
* **transfer-nc.txt (Хязгаарлалтгүй):** 36 мөр.
* **transfer.txt (Хязгаарлалттай):** 28 мөр. Хязгаарлалт нэмснээр утгагүй хослолууд хасагдаж мөрийн тоо цөөрсөн.
* **transfer-neg.txt (~ тэмдэглэгээтэй сөрөг утга):** 36 мөр. `~` тэмдэглэснээр сөрөг утгууд нэг мөрөнд хэт олноор давхцаж error masking үүсгэхээс сэргийлсэн.

#### Бодит 3 тест кейс (PICT гаралраас):
1. **Happy Path:** From: Valid, To: Valid, Amount: Normal, Currency: Same $\rightarrow$ **201 OK**
2. **Single Error:** From: ~Frozen, To: Valid, Amount: Normal, Currency: Same $\rightarrow$ **200 ERROR_FROZEN**
3. **Different Currency Boundary:** From: Valid, To: Valid, Amount: Normal, Currency: Different $\rightarrow$ **201 OK**

## Хэсэг B3: Дүгнэлт

Энэхүү лабораторийн ажлаар Category-Partition болон Microsoft PICT хэрэгслийг ашиглан банкны шилжүүлгийн функцэд тест дизайн хийж сурлаа. Гараар хийх Category-Partition арга нь алдааны семантик, давуу эрэмбэ болон бизнесийн логикийг нарийн тодорхойлох давуу талтай байсан. Нөгөө талаас PICT хэрэгсэл нь олон хувьсагчтай цогц системд pairwise covering array-г автоматаар үүсгэж, хүний анхаарнаас алдагдаж болох хослолуудыг бүрэн хамрах боломжийг олгодог. Гэвч PICT нь алдааны давуу эрэмбийг автоматаар ялгаж чаддаггүй тул `~` тэмдэглэгээ болон хязгаарлалтын дүрэм ашиглаж гаралтыг чиглүүлэх шаардлагатай болсон. Туршилтын явцад браузер болон шилжүүлгийн моделиудыг үүсгэж, команд мөрөнд үр дүнг results хавтас руу амжилттай бүртгэж авлаа. Greedy алгоритмын онцлог болон хосын хамралтын зарчмуудыг практик дээр хэрэгжүүлж үзсэн нь програм хангамжийн чанарын баталгаажуулалтад тест дизайн ямар чухал болохыг харууллаа. Энэхүү лаб нь тестийн комбинатор аргыг хөгжүүлж, автомат болон гар арга хоорондын ялгааг бүрэн ойлгоход чухал туршлага боллоо.
